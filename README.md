# Seatwise

校园座位预约平台。"系统分析与设计"课程项目，3 人开发，目标是解决校园里找座难、占座无人管、场馆方缺数据的问题。

## 背景

到图书馆或教学楼才发现没有空位，只能一层层找。座位被书本占着，人却一天不来。现有预约工具多是表单式的，只解决"订"，不解决治理、预测和解释。场馆方也拿不到利用率和违规数据，管理靠人工。

## 规划功能

- **预约引擎**：座位状态机覆盖预约、签到、离馆、超时。数据库事务加行锁做冲突检测，高峰并发不超卖。未签到自动释放，宽限期可配置，释放操作幂等。
- **信用治理**：迟到、爽约、占座扣分，良好行为加分。规则公开，分数影响可约时段与时长。
- **占用预测**：按区域和时段聚合历史数据，建立时序模型输出占用率预测，为错峰推荐提供依据。
- **对话助手**：自然语言描述需求，Agent 调用订座、预测、信用规则、报表等工具，确认后下单。也可以解释扣分原因、回答运营问题、对评价和投诉做聚类。LLM 只能查询和提议，订座、扣信用等后果性操作必须用户确认。没有 LLM 时核心流程照常可用。

## 仓库结构

```
seatwise/
├── backend/   Spring Boot 后端
├── frontend/  React 前端
└── ml/        预测模型与数据脚本
```

## 技术栈
- 前端：React 19 + TypeScript 6 + Vite 8，包管理 pnpm，lint 用 oxlint
- 后端：Java 25 + Spring Boot 4.1.1（spring-boot-starter-webmvc），构建用 Maven Wrapper
- ML：Python 3.14（uv + pyproject 管理）
- 数据库 MySQL，用事务 + 行锁实现并发一致性
- 接口：OpenAPI + Apifox，契约先行
- 部署：Docker Compose
- AI：LLM API + 统计/轻量时序模型

## 目标指标

- 表单预约 3 步内完成，对话订座端到端 < 3 s，核心接口 < 500 ms
- 并发不超卖，释放幂等，token 成本可控，预约数据不出域

## 风险与对策

- 并发一致性：事务 + 行锁 + 幂等设计，配合压测。
- LLM 幻觉、工具参数错误：确定性校验兜底，后果性操作人工确认。
- 成本与延迟：短上下文、缓存，核心流程不依赖 LLM。
- 隐私：预约数据不外发，对话不泄露他人预约信息。
- 预测冷启动：先用模拟数据跑通，再接真实历史数据。
